1. 背景与目标

当前团队采用 LangChain DeepAgents 作为 Agent Harness，使用 Langfuse 作为可观测与评估平台。编码 Agent 具有多步推理、工具调用、文件系统操作与子 Agent 委托等特性，传统单轮 LLM 评估（如 BLEU/ROUGE）已无法有效衡量其表现。

本方案目标：

  • 建立覆盖「结果 + 轨迹 + 效率 + 安全」的多维评估体系
  • 实现端到端可复现评估（Harbor 沙箱 + 确定性验证）
  • 与现有技术栈无缝集成，支持 CI/CD 质量门禁与生产闭环
  • 提供可落地的分数定义、Rubric 与代码模板

2. 评估理论框架

2.1 Agent 评估 vs LLM 评估

维度LLM 评估Agent 评估
类比学校考试工作绩效审查
关注点静态知识 / 单轮输出多步过程、工具使用、环境交互
成功标准答案正确性任务完成 + 轨迹质量 + 效率
主要挑战幻觉、事实性非确定性、长轨迹、环境依赖

2.2 四层评估模型

① 结果层

任务是否真正完成（测试通过、文件正确、目标达成）

② 轨迹层

工具选择、计划遵循、子 Agent 使用、错误恢复

③ 效率层

步骤数、Token、成本、冗余操作

④ 可靠性 / 安全层

pass@k / pass^k、Lucky Pass 检测、安全违规

核心原则：测试通过是必要条件，而非充分条件。必须同时评估轨迹质量，避免「碰巧成功」（Lucky Pass）。

4. 分数定义与 Rubric

4.1 Langfuse Score 定义

Score 名称 类型 范围 含义 推荐阈值
task_successNUMERIC0.0–1.0最终任务完成≥ 0.85
tool_selection_accuracyNUMERIC0.0–1.0工具选择正确率≥ 0.90
plan_adherenceNUMERIC0.0–1.0计划遵循度≥ 0.80
trajectory_efficiencyNUMERIC0.0–1.0步骤效率≥ 0.70
subagent_usageCATEGORICALnone/appropriate/overused/underused子Agent使用合理性appropriate
filesystem_correctnessNUMERIC0.0–1.0文件系统操作正确性≥ 0.90
lucky_passBOOLEAN0/1是否碰巧成功= 0
overall_qualityNUMERIC0.0–1.0综合加权分≥ 0.80

综合分加权公式：

overall_quality = 0.40×task_success
                + 0.25×tool_selection_accuracy
                + 0.15×plan_adherence
                + 0.10×trajectory_efficiency
                + 0.10×filesystem_correctness

4.2 工具评估 Rubric（摘要）

工具优秀 (1.0)差 (0.0)
write_todos合理分解、动态更新无计划或与执行脱节
read/write/edit_file必要操作、路径正确写错路径、未验证就写
execute命令正确、有错误处理危险命令、忽略错误
task（子Agent）正确隔离、结果正确合并过度委托或该委托却自己做

4.3 中间件评估要点

  • TodoListMiddleware：复杂任务（>3步）是否产生并同步 todo
  • FilesystemMiddleware：大结果是否被正确 offload
  • SubAgentMiddleware：是否真正实现上下文隔离
  • SummarizationMiddleware：压缩后是否保留关键事实

5. Harbor 对接方案

5.1 推荐方式：官方 DeepAgentsWrapper

# 安装
pip install "harbor[langsmith]"
# 或从 deepagents 仓库安装 evals

# 运行 Terminal-Bench
export ANTHROPIC_API_KEY=...
export LANGSMITH_TRACING=true

uv run harbor run \
  --agent-import-path deepagents_harbor:DeepAgentsWrapper \
  --dataset terminal-bench@2.0 \
  -n 4 \
  --env docker \
  --jobs-dir jobs/terminal-bench \
  --yes

5.2 自定义 langgraph 入口（更灵活）

langgraph.json

{
  "dependencies": ["deepagents>=0.7.0", "langfuse"],
  "graphs": {
    "deep_agent": "./agent.py:make_graph"
  }
}

agent.py 关键点

from deepagents import create_deep_agent
from deepagents.backends import LocalShellBackend

def make_graph():
    return create_deep_agent(
        model="anthropic:claude-sonnet-4-5",
        backend=LocalShellBackend(),  # 必须使用真实 Backend
    )
注意：必须使用 LocalShellBackend() 或兼容沙箱 Backend，否则文件系统为内存虚拟，无法真正操作终端环境。

6. 落地实施路线图

1

完善 Tracing（1–2 天）

所有 invoke/stream 注入 Langfuse CallbackHandler；关键工具添加 metadata。

2

建立黄金数据集（3–5 天）

从真实失败 PR / 生产 case 抽取 20–50 条任务，形成 Golden-PR 回放集 + Harbor Task。

3

实现确定性评估器 + Score（3 天）

实现 task_success、工具统计、Lucky Pass 检测，并写入 Langfuse Score。

4

对接 Harbor 端到端评估（3–5 天）

跑通 Terminal-Bench 子集 + 自建任务，建立 Resolve Rate 基线。

5

CI 集成与生产闭环（持续）

变更触发评估；生产失败回流黄金集；定期校准 LLM-as-Judge。

7. 核心代码示例

7.1 带 Langfuse 的运行与打分

from langfuse import get_client
from langfuse.langchain import CallbackHandler
from deepagents import create_deep_agent

langfuse = get_client()
handler = CallbackHandler()

agent = create_deep_agent(model="...", tools=[...])

with langfuse.start_as_current_observation(as_type="span", name="deepagent-run") as span:
    result = agent.invoke(
        {"messages": [{"role": "user", "content": user_input}]},
        config={"callbacks": [handler]}
    )
    trace_id = span.trace_id

# 打分
langfuse.create_score(
    name="task_success",
    value=1.0 if success else 0.0,
    trace_id=trace_id,
    data_type="NUMERIC"
)
langfuse.flush()

8. 最佳实践与风险提示

推荐

  • 始终固定 Harness 版本再比较模型
  • 报告 pass@1 + pass^k + 置信区间
  • 公共基准仅作能力基线，决策依赖内部黄金集
  • 轨迹优先，结果与过程并重
  • 生产失败即时回流评估集

风险

  • SWE-bench 等公共基准存在污染与测试缺陷
  • 分数高度依赖 Harness，跨脚手架不可直接对比
  • 长轨迹评估成本高，需采样或摘要
  • LLM-as-Judge 必须定期人工校准
  • 虚拟文件系统会导致评估失真
总结：以 Harbor 提供可复现的端到端 Resolve Rate，以 Langfuse 提供细粒度轨迹与自定义 Score，以内部 Golden-PR 集对齐真实业务分布。三者结合，形成「评估 → 分析 → 改进 → 再评估」的闭环，是编码 Agent 从 PoC 走向生产的关键质量保障。
本方案基于 Agent 评估理论研究、DeepAgents / Langfuse / Harbor 官方实践整理而成。
